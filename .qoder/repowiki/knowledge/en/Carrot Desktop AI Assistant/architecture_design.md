The repository is split into two cooperating child modules wired together by the root build and packaging layer. `carrot_core` exposes a FastAPI server plus a CLI entry point (`carrot start`, `carrot search`, etc.) defined in `pyproject.toml` under `[project.scripts]`. `electron_gui` launches that same FastAPI backend as a local HTTP service, hosts a React frontend, and bridges renderer ↔ Node via IPC. Both children share the same SQLite database under `data/` (gitignored) and communicate over localhost HTTP; the Electron process is the only GUI surface while the Python process remains the single source of truth for conversations, notes, goals, reminders, and search. `build.bat` orchestrates the full pipeline: install Python deps (`pip install -e .`), install Node deps, build the React frontend, then package the Electron app into `gui\dist\Carrot Setup.exe`. The root `README.md` and `PLAN.md` document the shared data model (SQLite + FTS5), Ollama integration at `localhost:11434`, and the hybrid search stack that both children consume.
